Look at what `/?subject=` does to your input. Request `/?subject=<b>test</b>`
and view the page source: your `<b>` tags reflect **without** being turned into
`&lt;b&gt;` — the value lands raw inside `<div class="subject">…</div>`.

Now try `/?subject=<script>alert(1)</script>` and view source again — the
`<script` and `</script` have been deleted. There **is** a filter, but it only
removes four exact substrings: `<script`, `</script`, `javascript:` and
`onerror=`. That is a _denylist_. It blocks specific spellings of "run
JavaScript", not the capability itself.

So the question is not "how do I get a `<script>` through" — it is "what other
markup runs JavaScript that this list never mentions?" And remember: running a
script in _your own_ browser gets you nothing. Whose browser holds the cookie
worth stealing, and what feature lets you hand that person a URL?
