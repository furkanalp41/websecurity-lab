The `?q=` search term is reflected into the page with no HTML escaping, so you
have a real HTML injection. But try the obvious payloads —
`<script>alert(1)</script>` and `<img src=x onerror=alert(1)>` — and nothing runs.

Read the response's `Content-Security-Policy` header. Its `script-src` has **no
`'unsafe-inline'`**, which is exactly why inline `<script>` and inline
`onerror`/`onclick` handlers are blocked. The CSP is a genuine barrier here; stop
trying to run inline script.

Now look at what `script-src` **does** allow, besides `'self'`. It names a second
host. A CSP host allowlist trusts that host completely — so the question becomes:
is there anything on that host that would hand you script execution?
