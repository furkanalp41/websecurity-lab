The `?ref=` value is reflected into `<head>` unescaped, so you have an HTML
injection — but the CSP is `script-src 'nonce-<random>'` with no `'unsafe-inline'`
and **no `'self'`**. Confirm what that blocks: an inline `<script>`, an
`<img onerror>`, and even a `<script src="/u/<id>/main.js">` pointing at same-origin
content all fail, because none of them carry the per-response nonce. You cannot
introduce a script of your own.

Read the CSP header carefully and think about what is **missing**, not just what is
present. `script-src 'nonce-…'` controls _which scripts may run_. There is a
separate directive that controls how **relative** URLs on the page resolve — and it
is not in this policy.

Now view the page source: the app's bundle is loaded as
`<script src="main.js" nonce="…">` — a **relative** path that already carries a
valid nonce. What decides where `main.js` actually points?
