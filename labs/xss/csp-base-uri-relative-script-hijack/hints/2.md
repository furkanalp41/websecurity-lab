A relative URL like `main.js` is resolved against the document's **base URL**. The
`<base href>` tag changes that base URL for the whole page — and the CSP directive
that would forbid a `<base>` from doing so, `base-uri`, is **absent** here. Your
`?ref=` injection lands in `<head>` **above** `<script src="main.js" nonce="…">`, so
an injected `<base>` applies to it.

The key insight: the nonce is an attribute on the `<script>` **element**, not a
property of the URL. So if you move where the page's _own_ nonced script resolves,
it still carries its valid nonce and the CSP still allows it — you do not need a
nonce of your own (you cannot get one anyway).

Point it at content **you** control on the same origin. Upload a script:

```
POST /upload   {"js":"...your bundle..."}
      →  {"id":"<id>", "path":"/u/<id>/main.js"}
```

(A _direct_ `<script src="/u/<id>/main.js">` is blocked — no nonce. That is why you
need the base.) What single tag, injected before the `<script>`, makes the page's
nonced `main.js` resolve under `/u/<id>/`?
