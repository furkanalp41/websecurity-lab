Look at **where** your input lands, not just whether it is reflected. Request
`/?promo=abc` and view the page source. `abc` does not appear in the page body —
it appears **inside an inline `<script>`**, between two single quotes:

```js
var promo = 'abc';
```

Now try `/?promo=<i>test`. The `<i>` is gone — the server strips `<` and `>`. So
the classic `<script>...</script>` payload is dead on arrival. But you are
already inside a script. In a **JavaScript string**, angle brackets mean nothing;
what ends the string is a single quote `'`. Try `/?promo=a'b` and look again: the
quote comes back **unescaped**. What could you do with a value that is allowed to
contain a quote?
