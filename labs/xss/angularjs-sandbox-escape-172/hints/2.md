`POST /report` (the "report this page to our staff" feature) queues a same-site
path that the admin bot then visits — carrying its `session` cookie, which is
**not** `HttpOnly`, so `document.cookie` can read it.

The escape you saw does not stop AngularJS because the browser **decodes** the
entities into the text node _before_ AngularJS parses the `{{ }}` expression. So
quotes inside your expression survive: escape `"` → `&quot;` and `'` → `&#x27;`,
and by the time AngularJS reads the node they are real quotes again. And crucially,
**AngularJS 1.6+ removed the expression sandbox** — so a `{{ }}` expression can
reach the `Function` constructor and run any JavaScript it likes.

The canonical AngularJS sandbox-escape gadget is:

```
{{ constructor.constructor("<your JS here>")() }}
```

`constructor.constructor` resolves to `Function`, so this is
`Function("<your JS>")()`.

Your plan:

1. Put a `{{ constructor.constructor("...")() }}` gadget in `?name=`.
2. Inside it, read `document.cookie` and send it somewhere you can read it. The
   only listener reachable from the bot's network is the collector at
   `http://collector:9000/` (the backend network has no internet route).
3. Submit that path via `POST /report` and wait for the bot.

How do you fire an HTTP GET to another host from JS without worrying about CORS? An
image load — `new Image().src = ...` — does exactly that.
