`POST /device/register` echoes back `{"ok": true}` for normal payloads, but a
single quote in the `X-FCTUID` header comes back with a database error. The
header reaches SQL. Try any obvious follow-up (`UNION SELECT`, `... FROM
information_schema.tables`, `SLEEP(5)`) and you get `403 blocked_by: acme-ips`.

Read the block message carefully — the response tells you _which_ rule tripped.
The IPS is a small keyword blocklist (SELECT, UNION SELECT, FROM,
INFORMATION_SCHEMA, SLEEP(, classic tautologies). It does not model SQL grammar;
it just pattern-matches on the decoded header value.

So the goal reshapes: you need to do something powerful _without ever typing any
of those keywords_. What Postgres feature runs a shell command as its own
`postgres` OS user — without a `SELECT` in the payload?
