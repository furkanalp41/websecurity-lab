The search is built with something like:

```python
Product.objects.extra(where=[f"title LIKE '%%{q}%%'"])
```

`.extra(where=[...])` splices that raw fragment into the query, and Django wraps
each extra `where` clause in **parentheses**. So the SQL that runs is roughly:

```sql
SELECT id, title, blurb, price_cents FROM app_product WHERE (title LIKE '%<q>%')
```

Two things to plan for:

- **Column count and rendering.** The results query selects **four** columns
  (`id, title, blurb, price_cents`), and the page shows `title` in the first
  cell. A `UNION SELECT` you add must return four columns too, with your secret
  positioned so it lands in the `title` slot.
- **Breaking out cleanly.** Your value sits inside `'%…%'` _and_ inside the
  parentheses `.extra()` added. To get a top-level `UNION`, you must close the
  string quote **and** that parenthesis, then neutralise whatever trails after
  your payload.

Where is the secret? Not in the product table. Django keeps user accounts in its
built-in `auth_user` table — and a `UNION` in this query can read across tables.
