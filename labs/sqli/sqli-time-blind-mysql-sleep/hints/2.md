The function you want is `SLEEP(seconds)`, and the question is _where_ to put it.
This endpoint performs an **INSERT**, not a SELECT — picture the statement the
developer built:

```sql
INSERT INTO hits (referrer, ua) VALUES ('<your ref>', '<your User-Agent>')
```

Your `ref` lands inside the first single-quoted value. That rules out `UNION`
(there is no result set to union with) and rules out reading a value back
(nothing is displayed). But an `INSERT ... VALUES` list can contain a **scalar
subquery** as one of its values — and a subquery can call `SLEEP()`.

Two things to line up:

1. **Break out and re-shape the VALUES list.** A `'` closes the `referrer`
   literal. After it you can supply the _second_ value as a subquery, then close
   the row's parenthesis. Count the parentheses carefully: the `IF`, the
   `SELECT`, and the `VALUES (...)` row each need closing.
2. **Comment away the tail.** Everything after your injection (the code's
   ` , '<ua>')`) must be neutralised. A MySQL line comment is two dashes **and a
   space**: writing `-- -` reliably includes that trailing space.

Try making the whole request sleep unconditionally first — e.g. a subquery that
runs `SLEEP(1)` no matter what — and confirm the response now takes ~1s. Once the
_mechanism_ works, wrap the `SLEEP` in `IF(<condition>, SLEEP(0.6), 0)` so it only
pauses when a condition you choose is true. What condition would reveal one
character of a secret at a time?
