Start by mapping the shape of the injection before you try to bypass anything.

Change `id` between real badges (`?id=2`, `?id=3`, `?id=4`) and watch the row
change — your value reaches the query. Now ask for the admin: `?id=1`. Nothing
comes back, even though a staff directory obviously has one. That means the row is
being _filtered out_ by the query, not that it is missing — there is a condition
you will need to work around.

Two observations decide everything that follows:

1. The value sits in a **numeric** slot (`... id=<id>`), not inside quotes. So the
   classic first move — a single quote to break out of a string — is not what you
   need here. You need to inject SQL _keywords_, and keywords must be separated
   from each other by something.
2. There is a homegrown request filter in front of the query. Don't guess what it
   does — ask it. `GET /debug?id=<value>` prints the exact bytes it forwards to
   the database. Send it a payload with spaces in it and read the output
   carefully. What happened to your spaces?
