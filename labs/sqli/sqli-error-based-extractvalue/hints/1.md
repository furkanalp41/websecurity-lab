Start by proving your input reaches the database. Change `assignee` between real
values (`alice`, `bob`, `carol`) and watch the ticket list change — so the value
is used in the query, not just displayed.

Now feed it something a normal name would never contain: a single quote,
`?assignee=alice'`. Read the banner carefully. A clean "no tickets" page would
mean your input is being handled safely. A raw MySQL error message means the
opposite: your quote broke the _syntax_ of a query the server built by pasting
your text into it.

Here is the key mindset shift for this lab: that error banner is not just a leak
of _how_ the query is built — it can be turned into a leak of the query's
_data_. Instead of trying to make results appear as rows (a UNION attack), think
about how you might make the database **fail on purpose** in a way that prints a
value you care about into the error text.
