MySQL has functions that expect well-formed XML/XPath and complain loudly when
they do not get it. The classic is `EXTRACTVALUE(doc, xpath)`. If the second
argument is not valid XPath, MySQL raises:

```
XPATH syntax error: '<the string you gave it>'
```

That means whatever string you hand to `EXTRACTVALUE` as the XPath comes straight
back to you in the error. So build that string out of a value you want to steal.
The trick is to start it with a character that is illegal at the start of an
XPath step — a colon (`:`, hex `0x3a`) — so MySQL rejects it and echoes it:

```
alice' AND extractvalue(1,concat(0x3a,(select api_key from secrets limit 1)))-- -
```

Two things to line up:

1. **Close the string and comment the tail.** Your value sits inside
   `assignee='...'`. Close it with `'`, add your `AND extractvalue(...)`, then end
   with a MySQL line comment — two dashes **followed by a space** — to neutralise
   the trailing quote. Writing `-- -` reliably includes that space.
2. **The subquery** `(select api_key from secrets limit 1)` is what gets rendered
   inside the error. The scenario names the table and its interesting column.

Fire that and read the banner. You will notice something frustrating about how
much of the value actually shows up — that is the puzzle hint 3 solves.
