The visible query returns **two** columns (`name`, `price`) and the first is text,
so put the value you want in the first slot and pad the second with `NULL`. The
target is `secrets.waf_bypass_flag`.

Instead of terminating the statement with a banned comment, **re-balance the string
literal**. The app wraps your input as `LIKE '%<q>%'`, so if your input ends with
`'%'='`, the app's trailing `%'` completes it into `'%'='%'` — a true comparison —
and every quote is balanced. Full value for `q`:

```
nonexistent%' /*!50000UNION*/ /*!50000SELECT*/ waf_bypass_flag,NULL /*!50000FROM*/ secrets /*!50000WHERE*/ '%'='
```

With the versioned comments interpreted, MySQL runs:

```sql
SELECT name, price FROM products
WHERE name LIKE '%nonexistent%' UNION SELECT waf_bypass_flag,NULL FROM secrets WHERE '%'='%'
```

`'%nonexistent%'` matches no products, the `UNION SELECT` appends the secret (in the
`name` position), and `'%'='%'` is always true. Check `/waf-log` — this request adds
**no** new block, confirming a clean bypass. The 32-hex value appears as one of the
"products" in the list. Copy it, then hand it to the win endpoint:

```
/solve?flag=<the 32-hex value>
```

(`/solve?token=<value>` works too.) A correct value returns the flag; a wrong one
returns 403. The secret is random per instance, so use the one _your_ container
printed. If you would rather not assume the table name, the same technique works
with `/*!50000FROM*/ information_schema.tables` to enumerate it first — no bare
keyword ever leaves your client.
