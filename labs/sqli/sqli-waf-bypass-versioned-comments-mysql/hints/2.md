The WAF matches keywords as **whole words** — its rules are effectively
`\bSELECT\b`, `\bUNION\b`, `\bFROM\b`, and so on (case-insensitive). A word
boundary (`\b`) only exists between a "word" character (letters, digits, `_`) and a
"non-word" character. So if a keyword has a **digit stuck to the front of it**,
there is no boundary before it and the whole-word rule never matches.

MySQL gives you exactly that for free. A **versioned comment** looks like:

```
/*!50000SELECT*/
```

It means "run `SELECT` if the server version is at least 5.00.00" — which MySQL 8
always is, so it simply runs `SELECT`. But to the WAF, the bytes are
`50000SELECT`: the `0` right before `S` kills the word boundary, so `\bSELECT\b`
does not fire. Try feeding one through and checking `/waf-log` — nothing new should
appear.

Two things still need care:

1. **Every** blocked keyword needs wrapping — `UNION`, `SELECT`, `FROM`, and
   `WHERE` all have rules. Wrap each one: `/*!50000UNION*/`, `/*!50000SELECT*/`, …
2. **You cannot use `-- ` or `#`** to comment out the rest of the query — both are
   blocked. So how do you deal with the trailing `%'` the app appends after your
   input, without a comment? (Hint: you do not have to comment it out. You can
   close your string and make the leftover into a harmless true comparison.)

Which table holds something worth stealing, and which of the two visible columns is
text? The scenario names the table.
