Start by mapping the two layers you are up against. First prove `q` reaches the
database: search for `phone`, then `cable`, and watch the product list change — so
the value is used in the query, not just echoed.

Now try the obvious injection, `?q=' UNION SELECT 1,2-- `. Instead of a database
error you get **HTTP 403** from `gizmo-waf`. This is important information, not a
dead end: a filter is rejecting your request _before_ the query runs. Open
`/waf-log` and read it — it lists the rule IDs that fired on your last blocked
request (for example `942100` for UNION, `942110` for SELECT, `942200` for `-- `).

Treat `/waf-log` as your feedback loop for the rest of the lab. The question to
carry forward: the WAF blocks the _word_ `UNION`, but does the database only
understand `UNION` when it is written as a bare word? MySQL has more than one way
to spell a keyword.
