This is a **second-order** injection. Your `User-Agent` is stored verbatim now,
and only later — when the dashboard renders — is each stored value pasted into a
query that counts how often that User-Agent was seen, roughly:

```sql
SELECT COUNT(*) FROM ua_events WHERE ua='<your stored User-Agent>'
```

Because your header lands _inside a single-quoted string_ in that statement, the
setup is perfect for a **UNION**: close the string, bolt on a second `SELECT`, and
neutralise whatever trails your injection.

Three things to line up:

1. **The column count must match.** The count query selects **one** column
   (`COUNT(*)`), so your `UNION SELECT` must also select exactly one column.
2. **The comment matters.** After your value there is a closing quote the server
   added. A MySQL line comment is two dashes **followed by a space**: `-- `.
   Writing `-- -` reliably includes that trailing space.
3. **Remember the two-step delivery.** You must _store_ the payload on one request
   (any request — it is your `User-Agent`), then _reload the dashboard_ to make it
   execute. It will not fire on the request that stores it.

So: what one-column value do you want, and from which table? The scenario names a
`settings` table with a per-instance secret.
