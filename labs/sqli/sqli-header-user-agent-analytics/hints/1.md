This lab has two moving parts, and only one of them is exploitable. Separate them
before you attack anything.

The **write** happens on every single request: the site records your `User-Agent`
header. The **read** happens only when someone loads the analytics dashboard at
`/admin/insights`, which summarises those stored User-Agents.

Try the obvious thing first and notice it does _nothing_: put a single quote in
your `User-Agent` and watch the response to that request — no error, no change.
That is a strong hint the value is being stored _safely_ (as a bound parameter).
So the vulnerability is not where your input goes _in_.

Where else does a stored User-Agent get _used_? Load `/admin/insights` before and
after sending a request with a quoted User-Agent, and compare the "Hits" table.
The bug lives on the path that _reads and re-uses_ what you stored earlier, not on
the path that stores it. What does that tell you about _when_ your payload runs?
