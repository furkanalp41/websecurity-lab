The `filter[...]` parameter is a dead end — it is bound as a hash condition, so
quotes and operators there are treated as data. Look at `sort` instead. Change
`?sort=id%20asc` to `?sort=id%20desc` and watch the _first_ row change. Your input
is reaching `ORDER BY`. And `ORDER BY` accepts far more than a column name.

There is no endpoint that prints the secret, and a broken query just returns
`{"error":"query failed"}`. So your only signal is **which row comes back first**.
How could a single yes/no fact about the secret change the order of the results?
