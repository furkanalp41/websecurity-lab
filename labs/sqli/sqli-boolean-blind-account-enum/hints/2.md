The header (`X-Account-Exists`) is driven by whether a database lookup on your
username returned a row. Ask _how_ that lookup is built. The value you send is
placed inside a single-quoted string in a SQL `WHERE username = '...'` check, and
it is glued in by concatenation — not bound as a parameter. That means you can
close the quote and append SQL of your own.

So the header is not just an "account exists?" flag. It is a readout of the
**truth value** of whatever condition ends up in that `WHERE` clause. This is
**boolean-based blind SQL injection**: no error text, no data echoed back — just
one true/false bit per request. That bit is all you need.

Try steering the bit yourself. Keep the real username so the row is found, then
`AND` a condition you know the answer to, and comment out the trailing quote the
server adds:

- `admin' AND (1=1)-- -` → the row still matches → header `true`
- `admin' AND (1=2)-- -` → the row is filtered out → header `false`

If those two behave differently, you fully control the oracle. Now point the
condition at something the _database_ knows but you do not — a column value in the
`users` table for the `admin` row — and you can start reading it out. Which column
in a reset/login system is worth reading? What Postgres function lets you compare
just **one character** of it at a time?
