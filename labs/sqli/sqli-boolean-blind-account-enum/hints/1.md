The response body is a decoy. The developer made `POST /forgot` return the exact
same JSON message and the same `200` status for every username on purpose, so that
the body alone can never tell you whether an account exists.

But a response is more than its body. Send two requests — one for a username you
believe is real (`admin`) and one for obvious junk (`totally-not-real`) — and
compare _everything_ that comes back, especially the response **headers**. One of
them changes depending on which name you sent.

That changing value is a one-bit signal: for any username you submit, the server
is telling you "this matched a row" or "this did not." Right now it only answers a
question you did not really need answered (does this account exist?). The whole
lab is about turning that same yes/no signal into a question _you_ choose. Keep
that header in view for everything that follows.
