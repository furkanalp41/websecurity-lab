The dashboard is honest but the header is not: `X-Account-Exists` leaks whether
your injected `WHERE` clause matched a row. That is a **boolean oracle** — each
request answers one true/false question, so you can extract data one step at a
time even though the response body never changes.

Shape of the attack:

- Inject into `username` so the query becomes
  `... WHERE username='admin' AND (<your condition>)`.
- Make `<your condition>` a comparison about ONE character of `admin`'s
  `password_hash`. Postgres `substring(...)` picks the Nth character and
  `ascii(...)` turns it into a code point you can compare with `<=`.
- A `<=` oracle means you can **binary-search** each character instead of trying
  every candidate — halve the range on each `true`/`false`.
- Repeat for positions 1..32, assemble the prefix, and submit it to `/solve`.

`/solve` is parameterised — don't inject there; `/forgot` is the only door.
