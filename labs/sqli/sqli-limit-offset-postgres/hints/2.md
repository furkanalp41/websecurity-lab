Your value lands in the `OFFSET` position of `... ORDER BY id LIMIT <size> OFFSET
<page>`. Do not reach for `UNION SELECT` — in Postgres a `UNION` cannot follow
`LIMIT`/`OFFSET`, so appending one is a syntax error (try it and read the
message). But Postgres _does_ accept an arbitrary integer **expression** there,
including a parenthesised subquery like `(SELECT 1)`. And the page prints database
errors back to you. So the plan is not "escape a string" and not "UNION" — it is
"put an expression in the OFFSET that fails in a way that spills the data I want
into the error." What happens if that subquery tries to turn text into an integer?
