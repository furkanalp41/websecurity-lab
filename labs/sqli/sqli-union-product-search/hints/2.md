Your value sits inside a single-quoted string in a `SELECT` that returns several
columns and prints them as a list. That is the perfect setup for a **UNION**
attack: you close the string, then bolt a second `SELECT` onto the first so its
rows appear alongside the shop's records.

Two things must line up before a `UNION` will run:

1. **The number of columns must match.** Ask the database directly. Try
   `?category=jazz' UNION SELECT 1-- -`, then `1,2`, then `1,2,3`, and read the
   error each time. MySQL literally tells you when the counts differ
   (`different number of columns`) and stops complaining once you get it right.
2. **The comment matters.** Everything after your injection (there is a trailing
   ` AND released=1`) must be neutralised. A MySQL line comment is two dashes
   **followed by a space**: `-- `. Writing `-- -` is a reliable way to include
   that trailing space.

Once you know the column count, the next question is _which_ of those columns is
printed as text — because that is where you will want your stolen value to land.
And _which_ table holds something worth stealing? The scenario names one.
