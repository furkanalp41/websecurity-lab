Start with the search itself, and forget the flag for a moment.

`searchReports(filter: String!)` does a "title contains X" lookup. That is a `LIKE`
query, and `LIKE` is exactly the kind of thing developers hand-write in raw SQL
even when the rest of the app uses an ORM. Ask yourself: what happens to your
`filter` string between the GraphQL argument and the database?

Send a few searches and watch the shape of the response:

- `query { searchReports(filter: "a") { id title } }` — some reports come back.
- `query { searchReports(filter: "zzzzz") { id title } }` — probably none.

The response is a _list_. It either has rows or it does not. Hold onto that idea:
"did this search return anything?" is a single yes/no bit. If you can make that bit
depend on something _other_ than the title text, you have an oracle — and the whole
lab is about choosing the question that bit answers.

Also poke `query { metrics { searchReportsCalls graphqlRequests } }` and notice it
tracks how many times the resolver runs. That endpoint only matters if you plan to
call the resolver a lot in one go. Wonder why you might want to.
