You have found it: when your `filter` names the `owner` key, _your_ value wins.
The server meant to run `owner == "guest" AND (your filter)`, but it merged the
two objects so that a colliding key overrides instead of narrowing. That means you
control the `owner` predicate — the very thing that was supposed to keep you out
of other people's documents.

This is **NoSQL / query-language injection** (CWE-943). In CouchDB the query is a
JSON "Mango selector," and top-level keys are ANDed together. Its operators
include `$eq`, `$ne`, `$gt`, `$lt`, `$regex`, `$or`, `$and`. So instead of a fixed
`owner` value, put an _operator_ there that is true for documents you do not own.

Two things to recall about CouchDB's ordering: `null` sorts below every real
value, and every document in this database has an `owner`. So ask yourself what
`{"owner": {"$gt": null}}` selects. Send `{"filter": {"owner": {"$gt": null}}}`
and read the `count` and `docs` in the response.
