Start by watching what the server tells you. `POST /find` does not just return
documents — it echoes back the `selector` it actually ran. That echo is a gift:
it shows you precisely how your `filter` and the server's access rule are being
combined.

Try three requests and compare the echoed `selector` each time:

- `{"filter": {}}` → the server runs `{"owner": "guest"}`. That is the access
  constraint, applied for you.
- `{"filter": {"title": "TODO"}}` → the server runs
  `{"owner": "guest", "title": "TODO"}`. Your key was _added_.
- `{"filter": {"owner": "someone-else"}}` → look very carefully at the echoed
  selector now.

The question the whole lab turns on: when your `filter` contains a key that the
server's constraint _also_ uses, whose value ends up in the final selector — the
server's, or yours?
