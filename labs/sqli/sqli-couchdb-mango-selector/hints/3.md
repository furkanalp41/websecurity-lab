`{"owner": {"$gt": null}}` matches every document in `restricted`, because your
key overrode the `owner == "guest"` constraint and every document's owner sorts
above `null`. In that full result set is a document you were never meant to see:
`_id` `flag_holder`, `owner` `"system"`, carrying a `secret` field.

Pin it directly by adding the `_id` to your filter (top-level keys are ANDed):

```
POST /find
{"filter": {"owner": {"$gt": null}, "_id": "flag_holder"}}
```

The response contains the `flag_holder` document, including its 16-character
`secret`. Redeem that secret for the flag:

```
GET /solve?secret=<the value of flag_holder.secret>
```

`/solve` is written the safe way — it never puts your input into a query — so it is
not injectable; the whole attack lives in the `/find` merge. `tests/exploit.py`
automates exactly these steps if you want to check your work.
