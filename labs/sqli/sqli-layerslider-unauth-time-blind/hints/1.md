The action `ls_get_popup_markup` needs no login and no nonce — it is registered
for anonymous callers. Good. But every request returns the identical `200 OK`
with the same markup, so there is no visible place to read data _out of_.

You have not lost the vulnerability, only the _visible_ channels. List what an
attacker can still influence: status code (fixed), body (constant), headers
(constant) — and one thing more, the **time** the request takes to come back.

Reframe the goal: you are not going to read data from the response, you are going
to make the database **pause on command** and use the presence or absence of that
pause as a one-bit answer. First, prove the `id` parameter reaches SQL at all —
what value would make the query take a couple of seconds longer than normal?
