Your first instinct — `id=1 AND SLEEP(3)` — comes back instantly with a
`security-policy` block (rule `942160`, "blind SQLi function SLEEP()"). Read that
carefully: the filter matched the literal token **`SLEEP(`** — the keyword
immediately followed by a parenthesis.

The filter looks at the raw parameter with a regex that treats only _plain
whitespace_ as allowed between the keyword and the `(`. What can you put between
`SLEEP` and `(` that (a) the regex does not count as whitespace, but (b) MariaDB
_does_ treat as whitespace? A C-style inline comment — `/**/` — does exactly
that. `SLEEP/**/(0.6)` executes but no longer matches `SLEEP(`.

Two more filter rules will bite if you are careless: quoted strings in an `OR`
context, and SQL line comments (`-- `, `#`). Avoid both by (a) encoding
`'admin'` as the hex literal `0x61646d696e`, and (b) keeping your injected clause
balanced so you never need to comment out the tail of the query.
