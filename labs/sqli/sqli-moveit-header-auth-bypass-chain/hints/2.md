Sessions are kept in a database table. The download handler looks a cookie up in
that table and checks `is_admin` and an expiry. If you could add a row to it with
values you choose, you would be "logged in" without ever authenticating.

Your injection is in an `INSERT`, and the driver (psycopg2 `.execute()`) runs
multiple `;`-separated statements in one call. So you can **stack** a second
`INSERT` after the audit one. The catch: the first insert must stay valid. The
audit insert writes three columns — `comment`, `client_ip`, `created_at` — so your
header has to supply the remaining two values and close that row before you start
your own statement:

```
x', '0.0.0.0', now()); INSERT INTO sessions (...) VALUES (...); --
```

The trailing `--` comments out the original query's leftover `', '<ip>', now())`.

session (think `is_admin`, `expires`, and a `token` you control)?
