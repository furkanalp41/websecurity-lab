# Hint 3

Use `$regex` with an anchored prefix to probe `reset_token`, targeting admin
specifically so decoys never interfere:

```json
{ "username": "admin", "reset_token": { "$regex": "^ab" } }
```

- HTTP **200** -> the token starts with `ab`
- HTTP **401** -> it does not

`reset_token` is a 64-character **hex** string, so at each position you only need
to try `0123456789abcdef`. Algorithm:

1. Start with an empty known prefix.
2. For the next position, test `known + c` for each hex char `c`. Exactly one
   returns 200.
3. Append that character to `known` and repeat until you have all 64 characters.

That is 64 rounds of at most 16 requests. If you fire the 16 probes for a position
in parallel it finishes in a couple of seconds. Then submit the full token:

```json
POST /solve   {"token": "<the 64 hex chars you recovered>"}
```

and read the flag from the response.
