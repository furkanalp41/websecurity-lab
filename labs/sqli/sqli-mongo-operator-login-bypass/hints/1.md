# Hint 1

The login endpoint speaks JSON, and the backend is MongoDB — not a SQL database.
So the usual `' OR 1=1 --` string tricks do nothing here.

Ask a different question: what if a field's value is not a string at all? In JSON
you can send an object where the server expected `"admin"`. MongoDB filters treat
certain objects as **operators**. Skim the Mongo docs for query operators such as
`$ne`, `$gt`, and `$regex`, and think about what `findOne({username: <something>,
password: <something>})` returns if `<something>` is `{"$ne": null}` rather than a
plain value.

Try sending an object instead of a string for `password` and watch the status
code change.
