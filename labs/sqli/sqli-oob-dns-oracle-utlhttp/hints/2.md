`UTL_HTTP` is the package. `UTL_HTTP.REQUEST('http://host:port/path')` opens a
TCP connection from the database process and issues a GET. If the app's Oracle
role holds `EXECUTE ON UTL_HTTP` and a matching network ACL, that request
succeeds and (crucially) reaches whatever listener you point it at.

Oracle 12c+ blocks this unless a SYS grant exists via
`DBMS_NETWORK_ACL_ADMIN.APPEND_HOST_ACE(host, ports, ace)`. The seed here
grants exactly one host: `oob` port 9000, over HTTP, for `REPORTAPP`. That is
your out-of-band channel.

Oracle doesn't allow stacked `;` statements in a normal SELECT, so you can't
just do `SELECT 1; BEGIN UTL_HTTP.REQUEST(...); END; --`. But your injection
sits inside a _string context_ (`region = '<here>'`). What SQL operator would
let you smuggle a call inside a string and _force_ Oracle to evaluate it? And
where would you read `secrets.oracle_secret` from as part of the same
expression?
