Try to run a second, stacked statement through the visible endpoint:
`category=web'; CREATE TABLE x(i int); --`. It fails —
`cannot insert multiple commands into a prepared statement`. That is asyncpg's
**extended (prepared-statement) protocol**, used by `.fetch()`, which allows only
one statement per call.

The other endpoint behaves differently. `POST /metrics/ingest` with a JSON body
`{"source":"...","category":"web"}` concatenates `source` into an `INSERT` that the
app runs with `.execute()` — the **simple query protocol**, which _does_ allow
several `;`-separated statements. It returns no rows, but it will happily run
whatever you stack after your injection.

So: one endpoint to **run** stacked statements (ingest, blind), one endpoint to
**read** results (metrics, visible). Now — what is the one command a PostgreSQL
**superuser** can run that executes a shell command on the server? Check
`SELECT current_user, usesuper` through the visible endpoint first.
